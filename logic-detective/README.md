# 🔍 逻辑小侦探

一个给 **9 岁左右小朋友**玩的、**完全离线**的中文逻辑与数学思维训练游戏。

不是刷题，是**破案**：孩子扮演小侦探，手上的「线索」是逻辑命题，要证明的「结论」是要破的案子。每走一步推理，都由一个**真正的数学证明内核**当场校验 —— 推错了立刻会被指出来，推对了就离破案近一步。

---

## 怎么玩

**双击 `开始游戏.cmd`** 就行。（在上一层目录还有个 `启动游戏.cmd`，效果一样。）

浏览器会自动打开游戏。玩完之后，关掉那个黑色窗口即可退出；
或者双击 **`停止游戏.cmd`**，它会自动找到并关掉后台的服务。

> 需要电脑上装过 [Node.js](https://nodejs.org)（免费，装 LTS 版即可）。
> 如果没装，也可以直接双击 `index.html` —— 游戏一样能玩，只是进度有可能存不住。
>
> 启动时提示「端口已经被占用」，说明上次没关干净 —— 先双击 `停止游戏.cmd` 再启动。
>
> **整个 `logic-detective` 文件夹就是完整的一份**，拷到别的电脑（甚至 U 盘）上照样能玩，
> 不需要联网、不需要安装任何东西（只要有 Node.js）。

> **给维护者**：三个 `.cmd` 都是**纯 ASCII**，这是刻意的。
> cmd.exe 按系统代码页（中文 Windows 是 GBK）读 `.cmd` 文件，而源文件是 UTF-8 ——
> 中文会被拆成错误的字节，`for /f` 那行直接解析崩掉，cmd 会跑去把中文当命令执行。
> 所以所有中文输出都交给 `serve.mjs` / `stop.mjs`（node 读 UTF-8 没问题）。
> **加脚本时请保持 .cmd 纯 ASCII。**

进度会**自动保存在浏览器本地**，关掉再打开还在。不需要联网，不收集任何数据。

## 里面有什么

一共 **10 个案件档案、108 关、18 次课**（每次约 30 分钟）：

| 档案 | 关数 | 孩子学到什么 |
|---|---|---|
| 🔍 **侦探入门** | 11 | ∧ ∨ ¬ → 四个符号**各有一页专门讲解**，先教，后考 |
| ⚖️ **等式的魔法** | 13 | **算术与替换**：等式像天平，`y = x+7` 就能把 y 换掉；`3+4` 算成 `7` |
| 🔗 **串起线索** | 11 | 「因为…所以…」；分辨哪条线索用得上；**目标到了就停** |
| 🧩 **拆开与合起来** | 11 | 「且」的拆与合；括号套括号 |
| 🔀 **两条路** | 11 | 「或」的用法；**分情况讨论**，甚至分情况里再分情况 |
| 🔢 **数字的秘密** | 15 | 奇偶性；**从两条公理推出 1+1=2**；succ 与单射性；**归纳法**；「举例」和「证明」的区别 |
| 🤔 **假设的力量** | 9 | ⊥ 是什么；**假设法**、**反证法**、**引理**、逆否命题 |
| 📦 **集合的箱子** | 9 | 证「A⊆B 且 B⊆C 则 A⊆C」；属于、包含、交集、并集 |
| 🏝️ **说谎岛** | 10 | 骑士与骗子：**一句话翻成两条线索**；**悖论**（证明「这种设定不可能」）；「一定」vs「可能」 |
| 🐍 **循环与递归** | 8 | **循环不变量**（开始/保持/结束三步）；**归纳法**；和递归是一回事 |

### 每个档案的节奏：学 → 练 → 测 → 总 → 创

每个档案都按同一个结构走，孩子熟悉了就知道每一步该干什么：

| 步骤 | 是什么 | 关卡类型 |
|---|---|---|
| **学** | 新概念、新工具，一页只讲一件事 | `teach` |
| **练** | 动手推理，从易到难 | `proof` |
| **测** | 选择题，检验「会不会分辨」 | `quiz` |
| **总** | **本课小结**：要点串一遍 + 毕业标准 + **用自己的话说一遍** | `summary` |
| **创** | **自己出一道题**：引擎当场判定成不成立 | `create` |

**跨档案还有一层：复习（间隔重复）** —— 见下文。

### 📚 课程模式：每课先复习，再学新的

关卡的组织方式（世界 / 课时）没变，在它上面另加了一条**「怎么走」的主线**：

从「📅 学习路线」点进去的每一课，都会按这个顺序走：

```
① 🔁 先复习（2~3 关，从前面所有课里挑）
② 📖 讲解新内容
③ ✏️ 练习
④ 🎓 小结（用自己的话说一遍）
⑤ 🎨 自己出题
```

顶部有一条进度条告诉你现在走到哪了：`📚 第 4 次 · ① 先复习　1 / 3`。

**为什么复习放在最前面，而不是学完再练？**

因为「**提取练习**」——努力从记忆里把东西拽出来的那一下，比再看一遍有效得多。
复习放在新课之前，等于每次都先考一次旧账，再学新东西。

复习题怎么挑：
- **到期的优先**（间隔重复算出来的）
- 其余按「**学得最早**」补 —— 越久没碰的越该复习
- 讲解页、小结页、出题关不参与复习（复习要的是回忆 + 动手）

第 1 课没有复习（前面还没内容），卡片上会直接写「第 1 课，不用复习」。

#### 🎓 小结关：写下来才算懂

小结页会把这一课的要点串一遍，然后问一句「用你自己的话说说…」，孩子写下来。

**不判对错** —— 判不了，也不该判。但有两个作用：

1. **写的过程就是复述**（费曼技巧）。能写出来，才是真懂了
2. 写下的内容会保存，家长可以看

#### 🕵️ 讲解关：找出推理里错的那一步

有人推了一段，其中**一步是错的**，让孩子抓出来。

为什么这关值得做：**会做一道题，和会检查别人的推理，是两种能力。**
后者更接近真实的数学和编程——你大部分时间都在看别人的东西哪里不对。

而且它好判分：点哪一步、对没对，机器直接就知道。

六个档案各有一个讲解关，**每个专治一种错**：

| 档案 | 错在哪 | 这个错的名字 |
|---|---|---|
| 串起线索 | 由「A → B」和「B」推出「A」 | **肯定了后件**（洒水车也能让地湿） |
| 拆开与合起来 | 从一半推整体 | 只有「高」，却合出「高 ∧ 胖」 |
| 两条路 | 只看一种可能就下结论 | 「或」漏了另一半 |
| 数字的秘密 | 试了几组就以为证明了 | **举例 ≠ 证明** |
| 假设的力量 | 「我没推出来」当成「推不出来」 | 反证法没真的推出矛盾 |
| 说谎岛 | 把「A → B」倒过来当成「B → A」 | 箭头掉头 |

> 最后那一个（说谎岛）**正是我自己在这份代码里犯过的错** ——
> 我当时只写了「骑士说真话」，漏了「骗子说假话」，
> 结果把一个无解的悖论当成了正常题。现在它变成了一堂课。

#### 🎨 出题关：反过来当老师
这是最难的一关：孩子从菜单里挑线索、挑结论，**引擎当场判定这题成不成立**。

判三条：

| 判定 | 孩子看到的提示 |
|---|---|
| 线索自洽？ | 「这几条线索互相打架，不可能同时成立」 |
| 结论不是废话？ | 「这个结论不用任何线索就成立，太简单了」 |
| 结论真能推出来？ | 「这个结论推不出来，线索不够」 |

**「出一道成立的题」比「做一道题」难得多** —— 而且这三条提示本身就在教「什么是一道好题」。

（这条判定标准和测试里用的是**同一套**，`tests/content.mjs` 会验每一道出题关至少存在一个成立的组合，否则孩子怎么试都过不了。）


### 说谎岛：为什么有些关的结论是 ⊥

骑士岛的规则是「一句话要翻成**两条**线索」：

> 甲说「P」　→　① 甲是骑士 → P（骑士说真话）
> 　　　　　　　② ¬甲是骑士 → ¬P（**骗子说假话**）

**只写①、漏掉②，是初学者最常犯的错** —— 而且会让人「推出」一些其实推不出来的结论。

两条都写上之后，有些故事就会变成**无解**：

> 甲说「乙是骑士」，乙说「甲是骗子」

四种可能性全都不成立。所以这几关的结论是 **⊥（不可能）** ——
孩子要证的不是"甲是什么"，而是"**这两个人不可能这样说话**"。

这比推出一个结论更有价值：它让孩子第一次看到，
**逻辑不只用来证明「是什么」，也用来证明「什么根本不可能」。**

### 复习：对抗遗忘

学完就忘是正常的。游戏里做了**间隔重复**：

- 每关第一次学会 → 排进复习，**1 天**后到期
- 到期后首页会自己冒出一个「🔁 复习（N 关到时候了）」按钮
- 复习时**自己想起来** → 排期推远（3 天 → 7 天 → 14 天 → 30 天）
- 复习时**看了提示** → 退回第一格，明天再来

孩子不用记该复习什么，**游戏记着**。

### 算术与「替换」

这一块参考的是世界闻名的 [NNG（Lean 自然数游戏）](https://github.com/leanprover-community/NNG4) —— 在那里，**第 2 关就是 `rw`（改写/替换）**，整个游戏都建立在自然数算术之上。

所以「等式的魔法」这个档案教三件事：

| 方法卡 | 是什么 | 对应 Lean |
|---|---|---|
| 🔁 **替换** | 既然 a = b，目标里的 a 全都可以写成 b | `rw [h]` |
| 🪞 **反着换** | 等式两边对称，反过来也能用 | `rw [← h]` |
| 🔢 **算一算** | 把能算的加法乘法算出来 | `norm_num` 之类 |
| ☑️ **两边一样** | 两边写得一模一样就结案 | `rfl` |

**线索和规则是两回事**，界面里也用颜色区分：

- **线索**（蓝）—— 关于**特定对象**的事实。`y = x + 7` 里的 y 就是 y。
- **规则**（琥珀）—— 普遍成立的**定律**。`n + 0 = n` 里的 n 是**空位**，什么都能塞进去。

（这个区分是数学上的实质区别，对应 Lean 里「假设 `h : y = x+7`」和「引理 `add_zero : ∀ n, n+0=n`」。早先我把两者混为一谈，结果 `a = b` 变成了「把任何东西换成 b」—— 不健全，测试当场抓出来了。）

数字档案最后还有一关硬骨头：**只给两条 Peano 公理，把 `1 + 1 = 2` 推出来**。孩子会第一次意识到，1+1=2 不是理所当然的，是可以被证明的。

### 为什么是这个顺序

顺序是**按内容**定的，同时看三条轴：

1. **依赖**（硬约束）—— 关卡不能用还没解锁的卡。这条决定了谁**不能**排在谁前面。
2. **熟悉度** —— 9 岁孩子课内已经懂奇偶和加法。数字关是**熟地**，该早点出现给信心，而不是排在抽象逻辑后面。
3. **难度节奏** —— 说谎岛最难（要把故事翻译成逻辑，还要用排中律），适合压轴。

由此得到：**认识符号 → 三个连接词 → 数字（熟地，只用得上前面的卡）→ 假设与反证 → 集合（要用「先假设」）→ 说谎岛（最难，收尾）**。

> 这里之前排错过。当时只按「证明内核的解锁顺序」这一条轴排，结果数字关被推到第 6 位、排在**最抽象的**说谎岛后面。同一个疏忽还有个副作用：卡片的「可用世界」和「介绍世界」是两份手写数据，已经漂移了（`只差一步` 声明第 2 个档案可用，实际到第 2 个档案第 4 关才介绍 —— 孩子会先看见卡，后看见介绍）。
>
> 现在两者合并成**唯一数据源**：谁能用，就看谁介绍过。并且有一条测试专门盯着「每一关只用孩子当时解锁的卡片就能做出来」。

每一关都配了 2–5 条**渐进式提示**，卡住时可以点「💡 提示」，不会直接给答案，而是引导下一步该想什么。

### 新词先介绍，不藏在题目里

孩子第一次遇到一个新词，不该是在被考的时候。所以：

- **每个符号都有一页专门介绍**（`type: "teach"`）—— 大符号、大白话、正反例子，讲完才出题。
- **每张方法卡第一次出现前，会弹「🎁 新道具」介绍** —— 说清楚它是什么、什么时候用、举个例子，点「知道啦」才进关卡。
- 这两件事都有测试盯着：介绍关必须排在世界最前面；每一关的新道具必须弹过一次介绍。

### 🎒 武器库

右上角的 🎒 随时可以打开，参考 lean4game 的 Inventory 做的：

- **方法卡**：按用途分组（结案 / 如果…那么… / 且 / 或 / 反证与进阶），每张都写着「什么时候用」和一个具体例子。
- **符号**：∧ ∨ ¬ → ⊥ 各自怎么读、什么意思、举个例子。
- **还没拿到的会显示 🔒 并告诉你哪个档案能拿到** —— 对孩子来说这是「再破几关就能解锁」的动力。

## 它是怎么保证「孩子推的是对的」

这是这个游戏和普通做题 App 最不一样的地方。

游戏内部是一个**真的证明检查器**，实现的是一阶逻辑里经典的**自然演绎**（natural deduction）。孩子点的每一张「方法卡」，背后都是一条数学上**可靠（sound）**的推理规则：

| 方法卡 | 背后的规则 |
|---|---|
| 🎯 就是它！ | 前提中已有结论 |
| 🔗 串起来 | 蕴含消去（假言推理）：有 P 和 P→Q，得 Q |
| 🪜 只差一步 | 后件推理：要证 Q，有 P→Q，则只需证 P |
| ✂️ 拆开线索 | 合取消去：P∧Q 得 P、Q |
| 🧩 合起来 | 合取引入：P、Q 得 P∧Q |
| 🎯 分开证明 | 合取引入（目标分解） |
| 👈 只证左边 / 👉 只证右边 | 析取引入 |
| 🔀 分情况讨论 | 析取消去：P∨Q，两条路都能到 R，则 R |
| 🤔 先假设 | 蕴含引入 / 否定引入 |
| ↩️ 反证法 | 归谬（经典逻辑特征规则） |
| 💥 出现矛盾 | 爆炸原理：有 P 和 ¬P，则一切都成立 |
| ⚖️ 一分为二 | 排中律：P 与 ¬P 两种情况各证一次 |
| 💡 先立个小目标 | 引理（cut）：先证一个中间结论再用它 |

**孩子不需要知道这些名字。** 他们看到的是「串起来」「分情况讨论」这样的说法，但底下跑的确实是这些规则。所以：

- 不可能「蒙对」—— 每一步都经过机器校验
- 也不可能「明明想对了却过不了」—— 规则集对经典命题逻辑是**完备**的

内核的可靠性有自动化测试兜底（见下文），包括「不能证明假命题」的健全性检查。

## 为什么没有直接用 Lean

原本是打算基于 [lean4game](https://github.com/leanprover-community/lean4game) 做一个本地实例的，Lean 工具链在这台机器上也能装能跑（`GameServer` 不依赖 Mathlib，中文界面也已内置）。最后没走这条路，原因是**目标**：

> 要培养的是**数学思维和逻辑能力**，不是学会 Lean。

真 Lean 对 9 岁孩子有几个硬障碍：

- 必须**打字**输入 `intro h` / `exact h` 这类命令，而且要完全正确
- 报错信息是**英文**的、面向程序员的
- 一关的抽象层次比「破案」高得多

这个项目保留了 Lean 最核心的两样东西 —— **形式化的推理规则**和**机器逐步校验**，但把交互换成了「点卡片」，反馈换成了中文鼓励语。

> 如果以后想让孩子接触真 Lean，`lean4game/` 和 `GameSkeleton/` 两个仓库已经克隆在工作区里，随时可以接着弄。

## 加关卡 / 改文案

**所有内容都在 `js/levels.js` 一个文件里。** 加一关只要往里加一段：

```js
{
  id: "chain-l6",
  world: "w1",
  type: "proof",
  title: "新的一关",
  newCards: [],                       // 这一关要介绍的新方法卡
  intro: "案情描述，支持 **加粗** 和换行。",
  givens: ["下雨", "下雨 -> 草地湿"],   // 线索
  goal: "草地湿",                      // 要证明的结论
  hints: ["先看哪条线索的结论正好是目标", "点 🔗 串起来"],
  conclusion: "过关语，讲讲这关的道理。",
}
```

公式写法（只有作者看得到，孩子永远不用输入）：

```
~A          非 A
A & B       A 且 B
A | B       A 或 B
A -> B      如果 A 那么 B
(A|B) & C   括号
```

原子命题直接写中文，**中间不要有空格**（比如 `小明在公园`）。

选择题则是：

```js
{
  id: "intro-q7", world: "w0", type: "quiz",
  title: "标题",
  question: "题干",
  options: [
    { text: "选项", correct: true,  why: "选它对/错在哪里的解释" },
    { text: "选项", correct: false, why: "……" },
  ],
  conclusion: "讲道理的部分。",
}
```

改完存盘，刷新浏览器就能看到。

想加一页**介绍**（先教后考那种），用 `type: "teach"`：

```js
{
  id: "intro-t5", world: "w0", type: "teach",
  title: "认识一个新符号：⊕",
  emoji: "➕",
  symbol: "⊕",                 // 页面上显示的那个大符号
  body: "这里支持 **加粗** 和换行。\n\n讲清楚三件事：它念什么、什么意思、举个例子。",
}
```

顺手在 `SYMBOLS` 里补一条，它就会出现在武器库里；给某张方法卡补一句 `CARD_GUIDE`，武器库里也会有「什么时候用 + 例子」。**忘了补的话 `npm test` 会提醒你。**

## 跑测试

改完关卡**一定要跑一遍测试**，它会替你检查出题有没有出错：

```bash
npm install          # 只装测试用的 jsdom，游戏本体不需要它
npm test
```

三层测试：

| 测试 | 检查什么 |
|---|---|
| `tests/smoke.mjs` | 内核本身：解析、真值表、走一步推理、健全性 |
| `tests/content.mjs` | **每一关内容**：① 结论真的能从线索推出来吗（用真值表独立验证）② 求解器真的能找到证明吗（否则孩子会卡死）③ 内核不能证明假命题 |
| `tests/ui.mjs` | **界面端到端**：用 jsdom 把整个游戏跑起来，像小朋友一样点按钮，**55 关全部点通**，并检查武器库、新道具弹层、零 JS 报错 |

`content.mjs` 的「可证性」检查特别有用：如果你出了一关结论其实推不出来的题，它会直接告诉你反例是什么。

它还盯着两件**教学设计**上的事：

- **先教后考** —— 世界 0 最前面必须是介绍关；介绍关不能排在选择题后面。
- **新词都要有说明** —— 每个符号得有介绍页，每张方法卡得有「什么时候用 + 例子」，武器库分组要覆盖全部卡片。

### 还有一个截图工具

jsdom 能验证「逻辑和流程对不对」，但它**不做 CSS 布局** —— 所以「弹窗没关掉」「按钮排得看不清」这类问题它一个都发现不了。这个工具用真的 Chrome 渲染并截图，用来肉眼检查：

```bash
node scripts/shots.mjs      # （在上一层目录跑）截图输出到 .shots/
```

（这个工具确实抓到过两个 jsdom 漏掉的真 bug：设置弹窗在首页就一直开着，以及目标公式 `A ∧ B ∨ C ∧ D` 缺括号、孩子读不懂。）

## 一点设计说明

几个刻意的选择，供参考：

- **不要求打字。** 全程点卡片。9 岁孩子的打字速度和拼写会成为认知负担，把注意力从「推理」引开。
- **符号做颜色编码。** 且=蓝、或=橙、非=红、蕴含=紫。抽象符号配固定颜色，孩子看久了会形成直觉。
- **只在能用的时候才让卡片亮起来。** 用不上的卡会灰掉，并说明原因 —— 这本身就在教「什么情况下该用哪条规则」。
- **错了只提醒，不惩罚。** 随时可以「↩️ 撤销」。孩子需要敢于试错才敢想。
- **「先假设」和「一分为二」都做成了正式规则。** 这两条是最容易被忽略、但数学家最常用的思考方式。
- **专门有一关讲「举例 ≠ 证明」。** 这可能是整个游戏里最重要的一课。
